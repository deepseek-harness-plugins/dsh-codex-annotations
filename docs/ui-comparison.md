# UI 尺寸对照

2026-10-08，版本 0.1.1。参考为用户提供的两张 Codex 选区/评论截图；实际验证使用 macOS DSH 0.2.0-rc.2 的 Web 客户端与 Chrome。

## 比较方法

原始参考截图为 604×206 与 752×336。根据文字与控件大小按 2x 截图推定，轮廓的人工定位约有 ±1 个实际像素误差；无法从图片恢复 Codex 原始 CSS 或确认截图缩放设置。dsh 对照采用明确的 Chrome `deviceScaleFactor: 2`，保留实际像素，没有放大低分辨率截图。控件裁切后按左上角对齐，逐像素取 RGB 通道差值。

参考中的菜单为 294×60、评论框为 592×92、编号为 54×54 个实际像素。下面使用折算后的布局尺寸；这些比较限于提供截图可确认的三个控件。

| 控件 | Codex 截图参考 | 0.1.0 | 0.1.1 宿主实测 |
| --- | --- | --- | --- |
| 选区菜单 | 147×30 | 约 199×51（样式推算） | 147×30 |
| 评论框 | 296×46 | 580×70 | 296×46 |
| 编号 | 27×27 | 25×25 | 27×27 |
| 菜单圆角 | 约 9 | 19 | 9，普通圆角 |
| 评论框圆角 | 约 23 | 24 | 23，胶囊轮廓 |
| 编号位置 | 选区末端上方 | 选区下半部，遮挡文字 | 末端上方；多行时移到整段选区上方 |
| 评论框与选区 | 左侧约偏移 -9，上方约 32 | 无偏移，上方 14 | 左侧偏移 -8，上方 31 |
| 批注区 | 未提供输入区截图 | 未与输入框对齐，三组重复标签 | 与原生输入框左侧、宽度相同；紧凑评论/原文胶囊 |

在 1280×900 窗口中，批注区和原生输入框均位于 x=420.5，宽 712。真实宿主测试同时覆盖窄窗口、深色评论框、多行代码编号的点击、原生输入和发送。

## 为适配 dsh 保留的差异

字体继承 dsh 原生字体；编号使用 `--dsw-alias-state-business-primary`，浅色实测为 `#4176E6`，参考截图主色约为 `#3A83F7`。浮层使用 dsh 的背景、文字颜色和面板阴影，避免重复描边；深色背景实测为 `#2C2C2E`。选区菜单底色为 `#C3DCFD`，待发送原文在白底上的高亮约为 `#A0D1FF`。

按用户要求不提供语音输入。参考中的麦克风位置换成中性的完成按钮；评论依然自动保存，Enter、Escape 和点击外部也可收起。原生「@ 批注」引用保留，以便使用 dsh 的发送及附件流程。

两张截图不能证明 Codex 全部交互行为。差值图包含字体抗锯齿、光标、图标、主题颜色、阴影和圆角外的背景内容差异，不把像素差异比例换算成整体相似度。

## 复现

执行 `npm run test:host`。`artifacts/ui-measurements.json` 包含实际 DOM 尺寸、样式和输入框对齐结果；`pixel-menu@2x.png`、`pixel-editor@2x.png`、`pixel-marker@2x.png` 包含 2x 原生渲染截图。用户原始参考和本地逐像素差值图不进入安装包。
